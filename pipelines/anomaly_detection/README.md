# Anomaly detection sample pipeline (Python)

This [solution guide](../../use_cases/Anomaly_Detection.md) reads UTF-8 messages from `transactions-sub`, calls a user-supplied Vertex AI endpoint through `RunInference` and `VertexAIModelHandlerJSON`, and publishes formatted predictions to `detections`. Input values must match the deployed model's expected instances. The current graph does not use the provisioned Bigtable and BigQuery resources; they are available for extensions.

## Configure and launch

First deploy the [application infrastructure](../../terraform/anomaly_detection/README.md) into an existing project and network. Supply an existing Vertex AI endpoint with a deployed model in that project. Terraform does not create or deploy the model.

From this directory, install `requirements.txt` in your Python environment, then:

```bash
source scripts/00_set_variables.sh
export MODEL_ENDPOINT="YOUR_ENDPOINT_ID"
# Optional when the endpoint is in a different region:
export MODEL_LOCATION="us-central1"
./scripts/01_build_and_push_container.sh
./scripts/02_run_dataflow.sh
```

`00_set_variables.sh` is generated by Terraform; change Terraform inputs and apply to regenerate it. It exports the project, region, selected bucket's `TEMP_LOCATION`, dedicated worker identity, container tag, worker sizing, full `INPUT_SUBSCRIPTION` and `OUTPUT_TOPIC` paths, and optional `SUBNETWORK` plus `NETWORK` compatibility alias.

The build script submits the existing `cloudbuild.yaml` with `_TAG=$CONTAINER_URI`, explicit project and region, and regional build storage. Ensure the build identity has push and staging permissions. Cloud Build uses `E2_HIGHCPU_8`. SDK/container versions are unchanged.

The launch script requires `MODEL_ENDPOINT` before submission. `MODEL_LOCATION` defaults to `REGION`. It uses streaming Dataflow, the custom container, a dedicated worker identity and disabled public IPs. It prefers `SUBNETWORK`, falls back to legacy `NETWORK`, and omits the subnet argument if both are empty. The unchanged defaults are at most one worker, a 200 GB disk and `g2-standard-4`; inference executes remotely on Vertex AI. Confirm machine availability and quota in the chosen region.

The existing network must provide Private Google Access, worker communication on TCP 12345/12346 for the `dataflow` tag, and NAT when internet access is needed. If no subnet is supplied, a usable default network must exist. Shared VPC URLs are supported; see the infrastructure README for IAM prerequisites.

## Input and output

Publish model-compatible UTF-8 messages to `transactions`. The pipeline decodes them as strings and sends them to the model without feature engineering. Read formatted input/prediction text from `detections-sub`, subscribed to `detections`.

For existing deployments, follow the infrastructure README's state migration guidance before applying the new configuration. Cancel or drain the streaming job before infrastructure cleanup.
